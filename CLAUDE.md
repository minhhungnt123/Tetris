# Tetris (Unity)

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 1. Project Overview

- Classic Tetris game (single player, local) built on **Unity 6**, editor version `6000.3.10f1` (see `ProjectSettings/ProjectVersion.txt`).
- Full set of modern Tetris guideline mechanics: 7-bag randomizer, SRS rotation + wall kick, ghost piece, hold piece, hard drop / soft drop, DAS/ARR for horizontal movement, flash effect on line clear, Tetris Guideline scoring (combo, back-to-back), level increases based on lines cleared.
- No backend/server, no save file beyond runtime memory — all state (score, history, board) only exists for the current session (`GameManager.ScoreHistory` resets when the Editor/build is closed).
- Run and test by opening the `Assets/Scenes/Tetris.unity` scene in the Unity Editor and pressing Play — there is no command-line build/test pipeline.

## 2. Tech Stack

- **Engine**: Unity Editor `6000.3.10f1` (Unity 6).
- **Language**: C#, compiled into the `Assembly-CSharp` assembly (`.csproj`/`.sln` files are auto-generated by Unity, not committed, never hand-edited).
- **Input**: Unity Input System (`com.unity.inputsystem` 1.18.0) — action maps defined in `Assets/InputAction.inputactions`, bound via `InputActionReference` in the Inspector.
- **UI**: uGUI (`com.unity.ugui`) + TextMesh Pro (`Assets/TextMesh Pro`) for text/buttons.
- **2D rendering**: Tilemap (`com.unity.modules.tilemap`) + `com.unity.feature.2d` — both the board and pieces are drawn with `Tilemap`/`Tile`, no per-block Sprites.
- **Visual Scripting** (`com.unity.visualscripting`) is installed in `Packages/manifest.json` but **not used** for gameplay — all current logic is plain C# scripts.
- **Test framework** (`com.unity.test-framework`) is installed but no tests have been written in the repo yet.
- See the full package list in `Packages/manifest.json`.

## 3. Architecture

Code is organized in a Manager / Controller / Core pattern under `Assets/Scripts/`:

- **Core/** — plain data, no MonoBehaviour.
  - `Tetromino.cs`: enum of the 7 piece types + `TetrominoData` struct (tile, cell shape, wall-kick table), populated via `Initialize()`.
  - `Data.cs`: static cell-shape table and SRS wall-kick offset tables (separate table for `I`, shared table for the other 6 pieces).
- **Managers/** — singletons (`Instance`, assigned in `Awake`) holding global state and firing events; other scripts subscribe rather than poll:
  - `GameManager`: score, level, lines cleared, combo/back-to-back multiplier, pause/game-over state. Fires `event Action`s (`OnScoreChanged`, `OnLevelChanged`, `OnGameOver`, `OnComboUpdated`, `OnBackToBack`, ...) for `UIManager`/`Board` to subscribe to.
  - `Board`: owns the `Tilemap`, the active `Piece`, the 7-bag randomizer (`_pieceQueue` + Fisher-Yates `RefillBag`), hold-piece logic, line detection/clearing (`ClearLinesAnimated` flashes then collapses rows, sets `IsAnimatingLineClear` to lock input/Update while running).
  - `InputManager`: the ONLY place that reads the Input System (`InputActionReference` from `Assets/InputAction.inputactions`). Converts raw input into semantic C# events (`OnMove`, `OnRotate`, `OnHardDrop`, `OnHold`, `OnSoftDropStart/Cancel`, `OnPause`).
  - `UIManager`: pure view layer — subscribes to `GameManager` events and toggles panels/text, contains no game logic of its own.
- **Controllers/** — behavior attached to the piece's GameObject in the scene:
  - `Piece`: per-frame gravity step, lock delay, hard drop, rotation (SRS rotation matrix + wall kick from `Data.WallKicks`), hold. Every position/rotation change goes through `Board.Clear(piece)` → mutate → `Board.Set(piece)`, and fires `OnPieceUpdated` when position/rotation actually changes (for `Ghost` to listen to).
  - `PlayerInputController`: translates `InputManager` events into calls on `Piece`, implements its own DAS/ARR for horizontal movement and soft drop. All input goes through `IsInputAllowed()` (blocks during pause, game-over, or while a line-clear animation is running).
  - `Ghost`: the shadow piece, always drops to the lowest valid position; only updates when `Piece.OnPieceUpdated` fires.

## 4. Rules (Mandatory)

- **Do not hand-edit** Unity auto-generated files: `*.csproj`, `*.sln`, `Library/`, `Temp/`, `Obj/`, `Logs/`, `UserSettings/` — they regenerate automatically when Unity opens the project.
- Every position/rotation change on `Piece` **must** follow the exact pattern `Board.Clear(piece)` → mutate → `Board.Set(piece)`. Skipping this step will desync the tilemap from the piece's logical state.
- **Must** check `Board.IsAnimatingLineClear` before adding any code that touches piece state — during the animation, both `Piece.Update()` and `PlayerInputController` must no-op.
- **Always null-check** `GameManager.Instance` / `InputManager.Instance` before subscribing or calling into them (they can be null due to `Awake` ordering or in edit-time contexts) — follow the existing pattern in the code, don't skip it.
- Score/combo/back-to-back math is calculated **only** inside `GameManager.AddScore` — never recompute or duplicate this logic elsewhere.
- `InputManager` is the only place allowed to read `InputActionReference`/Input System directly; other gameplay scripts only subscribe to the C# events it fires.
- This is a Unity Editor project — **do not** create CLI build/test scripts that assume a pipeline that doesn't exist; verify changes by running Play Mode in the Editor.
- Before reporting a UI/gameplay task as "done," you must explicitly state that it has not been tested in the Editor (since you don't have permission to run the Unity Editor headless) unless the user has confirmed they tested it.

## 5. Code Conventions

- Existing code comments are written in **Vietnamese** — keep this convention when adding new comments, don't switch to English mid-file.
- Singleton pattern: `public static X Instance { get; private set; }`, assigned in `Awake()`, `Destroy(gameObject)` if an instance already exists.
- Private fields use the `_camelCase` prefix (e.g. `_isLocking`, `_lineClearFlashDuration`); public properties use PascalCase, usually `{ get; private set; }` when only the owning class should set it.
- Events are named `OnXxx`, typed as `System.Action` / `Action<T>` (`OnScoreChanged`, `OnPieceUpdated`, `OnComboUpdated`, ...).
- Use `[Header(...)]` / `[Tooltip(...)]` to annotate fields shown in the Inspector — write tooltips in Vietnamese as in the existing code.
- Method names clearly describe the action, written out in full without confusing abbreviations (`HardDropPiece`, `RotatePiece`, `ClearLinesAnimated`).
- Event subscribe/unsubscribe always come in pairs inside `OnEnable`/`OnDisable` or `Start`/`OnDestroy` — never subscribe without a matching unsubscribe.

## 6. Skills (guidance by task type)

**Adding new input:**
1. Add the action in `Assets/InputAction.inputactions` (via the Unity Editor, or a script like `add_ui_input.py` for batch edits).
2. Add the corresponding `InputActionReference` + `event Action` in `InputManager`, subscribing/unsubscribing in `OnEnable`/`OnDisable`.
3. Listen for that event in `PlayerInputController` (or the relevant script) and call the matching method on `Piece`.

**Adding/changing a Tetromino type or wall kick:**
- Update `Data.Cells` and `Data.WallKicks` in `Core/Data.cs`, add an entry to the `Tetromino` enum if needed, assign the corresponding `Tile` to `Board.tetrominoes` in the Inspector.

**Adding a new UI panel/screen:**
- Add the panel GameObject in the scene, expose a corresponding field in `UIManager`, subscribe to an existing `GameManager` event (or add a new event if none exists) and toggle `SetActive` in the handler.

**Adding/changing scoring logic:**
- Edit `GameManager.AddScore`; if the UI needs to display something new, fire a new event following the `OnComboUpdated`/`OnBackToBack` pattern and handle it in `UIManager`.

**Adding animation/effects to the Board (line clear, etc.):**
- Follow the `IEnumerator` coroutine pattern used by `ClearLinesAnimated`, use a bool flag (like `IsAnimatingLineClear`) to block input/Update while the animation runs, and remember to reset the flag when the coroutine finishes.

## 7. Common Commands

- Open the project: open Unity Hub → select this project → make sure the Editor version is `6000.3.10f1`.
- Try the game: open the `Assets/Scenes/Tetris.unity` scene in the Editor → press Play.
- Regenerate the UI Action Map if `Assets/InputAction.inputactions` is missing the "UI" map: `python add_ui_input.py`
- Check the Editor version in use: read `ProjectSettings/ProjectVersion.txt`.
- Check the package/dependency list: read `Packages/manifest.json`.
- Git: standard git commands (`git status`, `git diff`, `git log`) — `.gitignore` follows the standard Unity convention, excluding `Library/`, `Temp/`, `Obj/`, `Build/`, `Logs/`, `UserSettings/`, `*.csproj`, `*.sln`, ...
